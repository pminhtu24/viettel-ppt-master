# Page brief rules (sub-agent and main agent)

These are the rules the checks cannot catch, plus the content bindings that `page_plan.py check <project> --pages <PID>` verifies. Everything that command reports (brand colors/fonts/weights, deep-blue scope, logo clearance, page number, backgrounds, rails, forbidden elements, spec_lock drift, text overflow, title zone, bindings, visual findings) you fix on your own SVG until it reports nothing. Never open the skill's scripts to learn these rules — this file and the check output are complete; each finding names the element and what to change.

1. **Content grounding** — show only facts, derived values and conclusions present in this page's content lock. Never add numbers, comparisons, trends, rankings or causal claims to fill a layout. Keep every meaning-bearing qualifier visible ("dự kiến", "khoảng", "kế hoạch", "lũy kế", period and scope); a number's period/scope label (KH tháng, Q3, lũy kế năm, tuần) is the one in its lock entry and stays next to it — never relabel, drop or invent it. `page_plan.py check` also traces your wording: a period label must be the one your bound source attaches to that number (same clause); keep "nguy cơ", "dự kiến", "chưa" with their status word and never add a status (chậm, vượt, đạt…) your bound source does not say; a place/project/unit named in a card heading must be the section of every number in that card; keep the noun after a ratio (`9/9 nhiệm vụ`, not `9/9`); a count in a title must equal the items listed. Never invent a name or abbreviation: a code such as `VTNT`, `QLVB` or `TTDL` that the source never writes is an error — use the source's own wording. Every `required` ID must be visibly represented. Never show internal identifiers (source block IDs such as `S…-B0006`, lock IDs, file names). Bind while you draw, not afterwards: root `<svg data-content-contract="1">`; every visible `<text>` (or its parent `<g>`) carries `data-claims="<IDs from this page's lock>"` naming exactly the facts/derived/conclusions it shows — a number may appear only in a text bound to an ID whose `text`/`raw`/`value` contains it, so never split a number from its locked phrase across lines; neutral headings, labels and the footer's section name bind to `c_label`; the footer's `Nguồn: …` is written from the `c_src` text of the lock (it may shorten it, its numbers come from there) and binds to `c_src`. Copy locked tokens verbatim, spacing and separators included (`2027 -2029` stays `2027 -2029`). Exempt only `data-chrome="page-number"` (digits) and `data-chrome="logo"`. (content-grounding §2, §3, §5)
2. **Chart geometry from the lock** — compute bar/point/arc geometry from the lock's values, never from the visible labels. (content-grounding §4, workflows/verify-charts.md)
3. **Chart markers** — each visualization in the lock whose template is not `none` is one `<g data-chart="<its id, e.g. v1>">` containing its marks and labels; chart pages also carry the `<!-- chart-plot-area: ... -->` comment. Deep blue `#12436D` only inside a group with `data-viettel-blue-scope="chart|diagram|icon|background"`, and never as a text fill (`[brand-deep-blue-text]`): numbers and labels are black, `#44494D`, or an accent color from rule 10. (content-grounding §3, executor-base §3.1)
4. **Rhythm** — `breathing` pages must not use multi-card grid layouts; `anchor` pages follow their template as-is. (executor-base §2.1, spec_lock_reference page_rhythm)
5. **Animation-ready groups** — 3–8 top-level content `<g id="...">` groups per slide; chrome groups use ids containing `header`, `footer`, `bg`, `background` or `decor`. (shared-standards Element Grouping)
6. **Summarise, never shrink** — a fact's `text` is the source, not the words to print. Write each block as a short phrase or one line (≈ 12 words) that keeps its numbers, period/scope labels, names, statuses and hedges exactly; drop optional blocks before anything else; show each figure once (no strip that repeats the table above it); never cut a sentence mid-way. The checker enforces: content text ≥ 18px, short single-line labels (≤ 24 characters, no `data-box`: axis/tick labels, legends, column heads, pills) ≥ 14px, ≤ 900 visible characters per slide (`[text-min-size]`, `[text-density]`); text inside `<g id="footer">` is exempt. Every text run in a card, table cell, chart lane or callout uses `data-box="x,y,w,h" data-wrap="true"` or manual line breaks as separate `<text>` elements, one per line — never `<tspan>` continuations inside one `<text>` (the overflow check measures the joined run). Keep card padding (18px body, 24px KPI). (executor-base §2.2)
7. **Match the anchor** — reuse the anchor SVG's header, divider, footer band, card, bar, table and status styling (rule 10); copy its `<g id="viettel-brand-chrome">` group unchanged on every page, chapter and ending pages included — only the page-number digits change (`page_plan.py check` compares it with the anchor). Never draw a second logo or page number. Read only this project's files and the skill templates your brief names; never open another project's SVGs. A script run on your page file (e.g. the anchor's `apply_brand_chrome.py`) rewrites it on disk — read the file back before your next write. (executor-base §3)
8. **Background marker** — a page with a `background` in its brief wraps that layer as `<g id="background-<id>" data-viettel-background-id="<id>" data-viettel-blue-scope="background">…</g>` with the brief's id; pages without one carry no such marker.
9. **Hand-written, one page at a time** — write each SVG directly; never generate SVG with a script. (SKILL.md rule 9)
10. **Viettel visual system — every content page** (cover, chapter and ending pages follow their layout template instead). A chart template gives the structure only; draw it in this system.
    - **Chapter and ending pages**: every chapter page reads "Chương N" (N = its order among the chapters, Arabic numeral) in the number slot and the chapter name below — the same format on all of them, whichever group draws them. The ending page title is a closing phrase ("Trân trọng cảm ơn!"), never the words "Trang kết"; a source disclaimer goes beneath it in small text.
    - **Frame**: header = red bar `x=64 y=38 w=7 h=38 rx=3.5` + title 30–32px bold at `x=88` in `data-box="88,36,960,58"` + divider `<line x1="64" y1="102" x2="1216" y2="102" stroke="#E6E6E6"/>`; at most one subtitle line, 18px `#44494D`, at y≈128. Footer band: `#F2F2F2` rect `y=674 h=46` full width, an 8px red stub at `x=0`, the brief's `section` at left (`x=40`, 14px weight 500, `#44494D`) and `Nguồn: …` right-aligned at `x=1170` (13px, `#44494D`). Content fills `y=132–650`.
    - **One focal point**: the page's key number or phrase, 32–48px bold, in red `#EE0033` or its status color. Everything else 18–20px, black or `#44494D`.
    - **Color carries meaning**: groups or series in order red → deep blue → teal `#28A197` → orange `#F46A25` → purple `#7C3AED`, then `#6B7280` for "Khác"; in chart and diagram marks the green may be emerald `#10B981` (dark `#059669`) instead of teal — one green per chart; purple and emerald only inside `data-viettel-blue-scope="chart|diagram"`, never text (green text is teal `#28A197`); your brief's `color recipe` line says how this page's chart type uses them; red leads every chart: columns of one measure red, the key column solid and the others red at fill-opacity 0.4; deep blue is the second series or the earlier period; gray only for tracks, gridlines and "Khác", never a data column; growth or above-plan the source states (tăng, vượt, +x%) teal or emerald, a decline or shortfall orange; done, 100% or "hoàn thành" teal; what the source calls "cảnh báo", "chậm", "nguy cơ" or marks `!` orange; incidents ("sự cố") red. A status color only where the source states that status (rule 1) — color the source's own symbol (▲, !) rather than inventing a status word. A bar's value label is 22–24px bold in the bar's color (black for tinted and deep-blue bars).
    - **Tints, not new colors**: a lighter shade is the same color with `fill-opacity` — 0.7 a second series of the same family, 0.45 plan, previous period or comparison values, 0.25 target zones and plan tracks, 0.12 pill and highlight-card fills, 0.06 a highlighted table row. Entities listed under `entity_colors` in the shared lock keep that color on every slide.
    - **Legibility**: when red and orange marks share a chart, write the value on each mark (they look alike to red–green color-blind viewers); white text on teal or orange only at 24px bold or larger — smaller text on them is black.
    - **Bars**: 16–24px thick, rx = half the height, on a `#F2F2F2` track that spans the content width. A bar row holds its label, its bar and its value — nothing stacked between rows; extra facts per row (tăng x%, % KH) go in their own right-hand column aligned across rows. Leave ≥ 12px between a bar and the next row's text. Rows in different units are drawn as % of their own plan with one shared 100% line. A label sits left of its bar on the same row; if it must sit above, it is ≤ 6px above its own bar and ≥ 14px below the previous bar, and a two-line label gets a taller row.
    - **Totals apart from their parts**: a cumulative or total (Lũy kế 9T, Cả năm, Tổng) never stands as a column on the same axis as the periods or parts it sums — it dwarfs them; show it as a KPI card or a label beside the chart.
    - **Cards**: white, `#E6E6E6` stroke 1.5, rx 10, a 6px colored stripe on the top or left edge (its group or status color), an icon 32–40px in that color, header 20px bold, body 18px. Status pill: 14px bold text in the status color on a rect of the same color with `fill-opacity="0.12"`, rx = half the height, carrying the source's own status word.
    - **Banner and callout**: a `#F2F2F2` band with a 6px red left stripe for the date, meeting or directive line; at most one callout per slide — a red 1.5px stroke box with a small red bold label — and only for a conclusion, kiến nghị or chỉ đạo the source states.
    - **Tables**: header row `#44494D` (or deep blue inside the chart scope) with white bold text, zebra rows `#F2F2F2`, numbers right-aligned, a status column as colored marks.
    - **Fill the space**: size rows, cards and numbers to the content area; short content gets bigger numbers and roomier rows, never an empty lower third. `page_plan.py check` reports `visual: …` when a content page has no accent color or ends above y≈470.
11. **Deck style** — the block after the binding pattern is the style the user confirmed for this deck; apply it on top of rule 10.
